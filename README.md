# XingHo Read

面向同学的英语口语跟读练习工具。把一段英文音频变成**能逐句听、逐句跟读、练完能打卡**的材料。

> **当前进度：Day 7 骨架版** —— 三个页面的界面已就位，真实功能尚未接通。
> 要做什么、做到什么程度算做到，见 `PRD.md`；用什么做、数据怎么走，见 `TECH_DESIGN.md`。

---

## 一、运行环境

- **Node.js**：建议 20 以上（本机实测 v24.21.0）
- **浏览器**：Chrome / Edge 最新版
- 第一次安装依赖需要联网

---

## 二、第一次运行（只需做一次）

在项目目录下打开终端，执行：

```bash
npm install
```

作用：把 React、Vite 等依赖下载到本机的 `node_modules` 文件夹里。

---

## 三、启动（每次开发都要做）

```bash
npm run dev
```

终端会输出类似这样：

```
VITE v8.3.0  ready in 327 ms

  ➜  Local:   http://localhost:5173/
```

然后在浏览器里打开 **http://localhost:5173** ，就能看到页面。

**要停止**：回到终端窗口，按 `Ctrl + C`。

---

## 四、其它命令

| 命令 | 作用 |

## 六、关于数据（重要）

本项目**不是纯前端应用**：数据存在**腾讯云 CloudBase** 上。

- **前端**（React + Vite）只负责界面，通过云函数接口读写数据
- **后端**是 CloudBase **云函数**（HTTP 型），对外提供 `/api/*` 接口
- **数据库**是 CloudBase **PostgreSQL**，三张表：`folders` / `materials` / `sentences`

| | |
|---|---|
| 好处 | 换浏览器、换电脑都能看到同一份数据；以后可以加账号与班级 |
| 代价 | **需要联网** —— 断网时读不到数据 |

> ⚠️ **本节以前写的是「纯前端、数据只存在你自己的浏览器里、断网也能用」**，
> 那是 Day 7–19 之前的情况。**Day 19 起数据已经迁到云端**，旧说法不再成立。
> 相关决策见 `TECH_DESIGN.md`；「断开网络后仍可见」这条 PRD 验收标准已登记为待办 **P0-4c**。

## 七、常见问题

**① 提示 `Port 5173 is already in use`（端口被占用）**

说明上一次的开发服务器还在跑。回到那个终端按 `Ctrl + C` 停掉；或者临时换个端口启动：

```bash
npm run dev -- --port 5174
```

**② 提示 `npm 不是内部或外部命令`**

说明 Node.js 没装好，或者没加进系统 PATH。重装 Node.js 并勾选「Add to PATH」。

**③ 页面打开是空白的**

先看终端里有没有红色报错；再按 `F12` 打开浏览器控制台，看 Console 里的报错信息。

## 八、发布前检查（Skill）

项目里有一个可复用的**发布前检查清单**：
`.workbuddy-ai/skills/xingho-release-check/SKILL.md`

### 什么时候用

- 把**前端或后端推到公网之前**
- **部署之后**要确认真的生效时
- 一天收尾、**准备提交时**

### 它查什么

R0–R5 六组共 **18 项**：

| 组 | 查什么 |
|---|---|
| **R0 红线** | 密钥没进仓库 / `.gitignore` 覆盖敏感文件 / 工作区干净且已推送 |
| R1 构建 | 前端能构建 / 后端语法正确 |
| R2 后端线上 | 健康检查 / 读接口 / **写操作四类闭环** / 错误提示是中文 / 环境变量还在 |
| R3 前端线上 | 公网首页 200 / 资源齐全 / **线上 JS = 本地构建的 JS** / 浏览器实测 |
| R4 数据卫生 | 库里没有测试残留 / 远端没有备份垃圾 |
| R5 文档 | `待办清单.md` 头行是今天 / 契约 = 实际路由 |

### 怎么用

1. 直接说「**跑一遍发布前检查**」，或
2. 手动打开 `SKILL.md`，按清单**逐条执行** ——
   ⚠️ **若是本次会话里刚创建的 Skill，工具层会加载不了**（技能只在会话启动时扫一次磁盘）。
   这时不要停下，手动执行一遍即可，原因与处置见 `Skill调用记录.md`。

### 两条要点

- **红线优先**：R0 任何一条不过 → 结论就是「**不许发布**」，不得因为「其他都过了」就放行。
- **不抄具体数值**：这个 Skill 里**不写**「库里应该有 5 个文件夹」这类数字，
  只写「查什么、用什么命令、什么算通过」。理由见 `SKILL.md` 的「铁律一」——
  写死了数字，将来合法变更就会让它变成一份**说谎的文件**。
